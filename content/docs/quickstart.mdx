# Quickstart

## Requirements

Before you begin, install the following:

- [Node.js](https://nodejs.org/) 20.9.0 or later, the minimum version that
  Next.js 16 supports

- `npm` that is bundled with Node.js

## Install and run {{productName}} locally for live preview

1. Create a new site, replacing `my-docs` with the name of your project
   directory:

   ```bash
   npm create beacon-docs@latest my-docs
   ```

   When prompted, enter a project name and the name of the product that your
   docs describe. The command downloads {{productName}}, adds starter pages,
   saves the product name in `.env.local`, creates a Git repository with an
   initial commit, and installs the dependencies.

1. Change to the project directory:

   ```bash
   cd my-docs
   ```

1. Start a local development server to preview your changes as you edit the
   content:

   ```bash
   npm run dev
   ```

   The development server runs at
   [http://localhost:3000](http://localhost:3000) and renders each page when
   you request it. It doesn't write the site to the `out/` directory. Changes
   to `content/nav.config.ts` reload automatically. To see changes to `.mdx`
   files, refresh the browser.

## Add a documentation page

1. Create a file under `content/docs/` for the new page, for example
   `content/docs/my-page.mdx`.

1. In the new page, add a frontmatter block to the file with a title and description:

   ```md
   ---
   title: My Page
   description: A short, specific summary of what this page covers.
   ---

   # My Page

   This is the content for my page.
   ```

   {{productName}} picks up the file automatically through the catch-all route and adds
   it to the client-side search index. The build also adds it to the sitemap.

1. In `content/nav.config.ts`, add a link to the page in the navigation, add an
   entry for the new file to a group's `items` array, for example the **Get
   Started** group:

   ```ts
   { title: "My Page", href: "/my-page" }
   ```

1. With the development server running, open
   [http://localhost:3000/my-page](http://localhost:3000/my-page) to view the
   new page.

## Push the changes to GitHub

1. On GitHub, [create a new repository](https://github.com/new). Leave it
   empty.

   Don't add a README, `.gitignore`, or license.

1. On your local machine, commit the page that you added and the
   `content/nav.config.ts` file, connect your local repository to the new
   GitHub repository, and push:

   ```bash
   git add .
   git commit -m "Add my page"
   git remote add origin https://github.com/<your-username>/<your-repo>.git
   git push -u origin main
   ```

   Replace `<your-username>` and `<your-repo>` with your GitHub username and
   the name of the repository that you created.

## Deploy to Vercel

Deploy the site to Vercel to publish it. Vercel builds the site from a GitHub repository when you push to the `main` branch. You can also deploy preview builds for other branches.

1. In the Vercel dashboard, [import the repository](https://vercel.com/new).
   Leave the build settings at their defaults. Vercel detects the Next.js
   static export automatically.

1. Under **Environment Variables**, add the following variables:

   - `NEXT_PUBLIC_PRODUCT_NAME`: the product name from your `.env.local` file.
     The `.env.local` file isn't committed, so Vercel can't read it.

   - `NEXT_PUBLIC_SITE_URL`: your site's URL, for example
     `https://my-docs.vercel.app`.

1. Click **Deploy**. After the first deployment, every push to `main`
   triggers a new production deployment, and pushes to other branches create
   preview deployments.

1. Open `https://<your-project>.vercel.app/my-page` to view the new page.

To preview the static build locally, see
[Deployment](/deploy).
