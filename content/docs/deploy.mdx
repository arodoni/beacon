# Deployment

{{productName}} builds to a plain static site. There's no server-side runtime to provision: `npm run build` produces an `out/` directory of HTML, CSS, and JS.

## 1. Set environment variables

Set these before running a production build, not after:

| Variable                 | Required           | Purpose                                                                 |
| ------------------------ | ------------------- | ------------------------------------------------------------------------ |
| `NEXT_PUBLIC_SITE_URL`   | Recommended         | Full public URL of the deployed site. Used for canonical links, Open Graph tags, `sitemap.xml`, `robots.txt`, and `/llms.txt`. Falls back to `https://example.com` if unset. |
| `NEXT_PUBLIC_BASE_PATH`  | Only for subpaths   | Subpath the site is served from, e.g. `/repo-name`. Leave unset for root-domain hosts like Vercel. |

Set `NEXT_PUBLIC_SITE_URL` in the Vercel dashboard rather than committing production URLs to `.env.local`.

## 2. Build and verify locally

```bash
npm install
npm run build
```

Preview the exact static output before pushing:

```bash
npm run start
```

This serves the `out/` directory as-is with no Next.js server involved, so it's the closest local approximation of production.

Optionally run the Playwright suite against the app first:

```bash
npx playwright install chromium   # one-time browser download
npm run test:e2e
```

## 3. Deploy

### Vercel

1. Import the repository in the Vercel dashboard.
2. Leave the build settings at their defaults; Vercel detects the Next.js static export automatically.
3. Add `NEXT_PUBLIC_SITE_URL` under Project Settings → Environment Variables, set to the assigned or custom domain.
4. Deploy. Every push to `main` triggers a new production deployment; other branches get preview deployments.

## 4. Verify after deploy

- Load the deployed URL and confirm the sidebar, search (`Cmd/Ctrl+K`), and dark mode toggle work.
- Check `/sitemap.xml`, `/robots.txt`, and `/llms.txt` resolve and reference the correct production domain, not `example.com`.
- If the site is served from a subpath, click through a few internal links to confirm `NEXT_PUBLIC_BASE_PATH` was applied consistently to both pages and static assets.

See [Troubleshooting](/troubleshoot) for fixes to common build and deployment issues.
