# Deploy the documentation site

## Push the changes to GitHub

<Steps>
  <Step title="Commit the changes">
    On your local machine, commit the page that you added, `my-page.mdx`, and the
    `content/nav.config.ts` file:

    ```bash
    git add .
    git commit -m "Add my page"
    ```
  </Step>

  <Step title="Connect the remote repository">
    Connect your local repository to the new GitHub repository. Replace
    `<your-github-username>` with your GitHub username:

    ```bash
    git remote add origin https://github.com/<your-github-username>/my-docs.git
    ```
  </Step>

  <Step title="Push to main">
    Push the changes to the `<your-branch>` branch:

    ```bash
    git push -u origin <your-branch>
    ```

    <Callout type="tip">
      If the push fails with `Password authentication is not supported for Git operations`, GitHub rejected your account password.

      - If you've added an SSH key to your GitHub account, switch the remote to SSH by running `git remote set-url origin git@github.com:<your-github-username>/my-docs.git`, and then push again.

      - Otherwise, when Git prompts for a password, enter a [personal access token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) instead.
    </Callout>
  </Step>
</Steps>

## Deploy the site to Vercel

Deploy the site to Vercel to publish the new documentation. 

Vercel builds the site from the GitHub repository when you push to the `main` branch. 

{{productName}} picks up the files automatically and adds them to the client-side search index.

The build also adds the new pages to the sitemap.

<Steps>
  <Step title="Deploy the site">
    In the Vercel dashboard, click **Deploy**. After the first deployment, every
    push to `main` triggers a new production deployment, and pushes to other
    branches create preview deployments.
  </Step>

  <Step title="View the live page">
    Open `https://<your-vercel-domain>/my-page` to view the new page.
  </Step>
</Steps>

## Verify the deployment

- Load the deployed URL and confirm the sidebar, search (`Cmd/Ctrl+K`), and dark mode toggle work.

- Check `/sitemap.xml`, `/robots.txt`, and `/llms.txt` resolve and reference the correct production domain, not `example.com`.

- If the site is served from a subpath, click through a few internal links to confirm `BASE_PATH` was applied consistently to both pages and static assets. This does not apply when you deploy the site on Vercel.

See [Troubleshooting](/troubleshoot) for fixes to common build and deployment issues.
