# Release Notes

## 2026-10-14

- Added custom docs variables. Define your own variables as names and string
  values in `content/variables.json`, and use them in pages the same way as the
  built-in `productName` and `projectName` variables. To show a variable name
  as literal text, put a backslash in front of it. See
  [Format Content](/format#add-your-own-variables).

- Added `Steps` and `Step` components (`src/components/docs/Steps.tsx`) for
  numbered procedures in docs content. Each step shows a numbered badge, a
  title, and a connecting line to the next step, and numbers itself
  automatically. They're registered as global MDX components, so any `.mdx`
  file can use `<Steps>` and `<Step title="...">` without an import statement.
  See [Format Content](/format).

## 2026-10-13

- Added `create-beacon-docs`, a command-line tool that creates a new
  {{productName}} site. Run `npm create beacon-docs@latest my-docs` to download
  {{productName}} with starter pages in place of its own docs, set your product
  and project names, start a Git repository, and install dependencies in one
  step. The source is in `packages/create-beacon-docs/`.

- Added a `NEXT_PUBLIC_PRODUCT_NAME` environment variable for the name of the
  product your docs describe. It sets the top bar, page titles, and the
  `productName` docs variable, and falls back to `MyProduct` if unset. See
  [Deploy](/deploy).

- Added an `.env.example` file that lists the environment variables you can
  set. It doesn't include keys, secrets, or tokens.

## 2026-08-19

- Update Monitoring on Dashboard now shows a status badge on each suggestion,
  with *Accept* and *Dismiss* buttons for pending suggestions. See [Doc Update
  Automation](/doc-updates) for details.

## 2026-08-12

- Added a `Callout` component (`src/components/docs/Callout.tsx`) for note, tip,
  important, and warning admonitions in docs content. It's registered as a
  global MDX component, so any `.mdx` file can use `<Callout
  type="warning">...</Callout>` directly without an import statement.

- Added a `DOC_UPDATE_AUTOMATION_ENABLED` environment variable to gate the doc
  update automation webhook. It's disabled by default; set it to `true` to turn
  the automation on. See [Doc Update Automation](/doc-updates) for details.

## 2026-08-05

- Added this Release Notes page to track new features going forward.

- Added a GitHub webhook that triggers when a PR merges into `main` touching
  `content/docs/**/*.mdx` or `content/nav.config.ts`. It checks whether other
  doc pages are now stale and writes suggestions to Vercel Blob storage for
  manual review. See [Doc Update Automation](/doc-updates) for details.
