# Authoring Reference in {{productName}}

## Markdown and MDX

{{productName}} uses [MDX](https://mdxjs.com/) to author documentation pages. MDX is Markdown with embedded JSX components.

In {{productName}}, you can use standard Markdown syntax to format text,
create headings, lists, links, and code blocks. You can also use MDX
components, described in the following sections.

## Table, task list, and strikethrough

Tables, task lists, and strikethrough work through `remark-gfm` in {{productName}}.

The examples below specify a table, checked and unchecked items, and a
strikethrough text:

```markdown

| Table column1 | Table column2 | Table column3 |
| --- | --- | --- |
| Table cell | Table cell | Table cell |

- [x] Task list1
- [ ] Task list2

~~Anything else~~ not needed
```

The above snippets render as:

| Table column1 | Table column2 | Table column3 |
| --- | --- | --- |
| Table cell | Table cell | Table cell |

- [x] Task list1
- [ ] Task list2

~~Anything else~~ not needed

## Callouts

Use the `Callout` component to highlight notes, tips, important information, and warnings.

For example: 

```markdown
<Callout type="note">
  This is a note callout.
</Callout>
```

Sample renderings: 

<Callout type="note">
  This is a note callout.
</Callout>

<Callout type="tip">
  This is a tip callout.
</Callout>

<Callout type="important">
  This is an important callout.
</Callout>

<Callout type="warning">
  Always keep your API keys private. Do not share them in public repositories.
</Callout>

## Steps

Use the `Steps` and `Step` components to show a procedure as a numbered sequence, without an import statement. Each `Step` takes a `title` and numbers itself, so you can add, remove, or reorder steps without renumbering them.

For example: 

```markdown
<Steps>
  <Step title="Install the dependencies">
    Run `npm install`.
  </Step>
  <Step title="Start the development server">
    Run `npm run dev`.
  </Step>
  <Step title="Open the site">
    In a browser, go to `http://localhost:3000`.
  </Step>
</Steps>
```

The above snippet renders as:

<Steps>
  <Step title="Install the dependencies">
    Run `npm install`.
  </Step>
  <Step title="Start the development server">
    Run `npm run dev`.
  </Step>
  <Step title="Open the site">
    In a browser, go to `http://localhost:3000`.
  </Step>
</Steps>

## Images and videos

To add an image or video to a page, put the file in the `content/media/`
folder, then insert it with the `Image` or `Video` component. You don't need
an import statement. Supported file types are `.svg`, `.png`, `.jpg`, `.jpeg`,
`.gif`, `.webp`, `.avif`, `.mp4`, `.webm`, and `.mov`.

For example, with `content/media/dashboard.png` and
`content/media/setup-demo.mp4`:

```mdx
<Image src="dashboard.png" alt="The dashboard with two connected projects" />

<Video src="setup-demo.mp4" title="Connecting a project" caption="Connect a project in under a minute." />
```

Set `src` to the file's path inside `content/media/`, such as
`screenshots/dashboard.png` for a file in a subfolder. You can also set `src`
to a full URL, such as `https://example.com/diagram.png`. The build fails if
`src` points to a file in `content/media/` that doesn't exist.

Both components take these properties:

| Property | Component | Required | Description |
| --- | --- | --- | --- |
| `src` | Both | Yes | The file in `content/media/`, or a full URL. |
| `alt` | `Image` | Yes | Text that describes the image for screen readers. |
| `title` | `Video` | Yes | A short name for the video, read by screen readers. |
| `caption` | Both | No | Text to show below the image or video. |
| `width` | `Image` | No | The image width in pixels, in quotes, such as `width="320"`. By default, the image is its natural width, up to the width of the page. |
| `poster` | `Video` | No | An image in `content/media/` to show before the video plays. |
| `autoPlay` | `Video` | No | Add `autoPlay` with no value to play the video automatically, muted and on a loop, like an animated GIF. |

You can also insert an image with Markdown image syntax, such as
`![The dashboard](dashboard.png)`. Use the `Image` component when you want a
caption or a set width.

The development server copies `content/media/` when it starts, so restart it
after you add or change a file.

## Docs variables

To insert a variable in a page, write its name inside double curly braces.
Variables work in frontmatter and in the page body, including inside code
blocks.

{{productName}} has two built-in variables:

| Variable | Value |
| --- | --- |
| `productName` | The product name |
| `projectName` | The project name |

The build fails if a page uses a variable that doesn't exist.

### Add your own variables

To define more variables, add them to `content/variables.json` as names and
string values. For example:

```json
{
  "supportEmail": "support@example.com",
  "latestVersion": "2.4.0"
}
```

Then reference them in a page:

```mdx
---
title: Get help
description: How to contact support about version \{{latestVersion}}.
---

# Get help

If you have questions about version \{{latestVersion}}, email
[\{{supportEmail}}](mailto:\{{supportEmail}}).
```

The page renders as "If you have questions about version 2.4.0, email
support@example.com." Restart the development server after you edit
`content/variables.json`.

Variable names can contain only letters, digits, and underscores, and can't
reuse a built-in name. The build fails if the file isn't valid JSON or if a
value isn't a string.

### Show a variable name as literal text

To show a variable's name in curly braces without replacing it, for example in
a code block, put a backslash in front of it. `\\{{productName}}` renders as
`\{{productName}}`.

This works in code blocks, inline code, and frontmatter. In regular text, MDX
treats curly braces as code, so an escaped variable renders as nothing. In
regular text, put a backslash in front of each opening brace instead. For
example, this line in a page:

```mdx
To insert the product name, type \{\{productName}} in your page.
```

Renders as:

```text
To insert the product name, type \{{productName}} in your page.
```
