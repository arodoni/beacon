# Configuration

See [Requirements](/quickstart#requirements) if you haven't set up {{productName}} locally yet.

## Page frontmatter

Every file in `content/docs/` supports the following frontmatter fields:

| Field         | Type   | Required | Description                                  |
| ------------- | ------ | -------- | --------------------------------------------- |
| `title`       | string | yes      | Used as the page `<title>` and page heading.  |
| `description` | string | yes      | Used for the meta description and search.     |

## Sidebar navigation

`content/nav.config.ts` is the single source of truth for the sidebar. It exports a list of groups, each with a title and an ordered list of items:

```ts
export const nav: NavGroup[] = [
  {
    title: "Get Started",
    href: "/",
    items: [
      { title: "Introduction", href: "/" },
      { title: "Quickstart", href: "/quickstart" },
    ],
  },
  {
    title: "Release Notes",
    href: "/release-notes",
    items: [],
  },
];
```

Every group requires a `href` in addition to its `items` list. A group's `items` can be empty when the group's `href` alone should serve as its landing page, as with Release Notes above.

Every `href` must resolve to either `/`, `/dashboard`, `/dashboard/editor`, or a slug that matches a file in `content/docs/`. The build checks this and fails loudly if a nav entry points nowhere, rather than shipping a broken link.

## Product and project names

{{productName}} uses two names:

| Name | Set in | Used for |
| --- | --- | --- |
| Product name | `NEXT_PUBLIC_PRODUCT_NAME` environment variable | The top bar, page titles, and the `productName` docs variable. Falls back to `MyProduct` if unset. |
| Project name | `projectName` in `src/lib/site.ts` | The `projectName` docs variable, for example in repository URLs. |

For local builds, set `NEXT_PUBLIC_PRODUCT_NAME` in `.env.local`. For
production, set it in your hosting provider's dashboard. See
[Deployment](/deploy#1-set-environment-variables).

## Docs variables

To insert the product name or project name in a page, write the variable name
inside double curly braces. Variables work in frontmatter and in the page body,
including inside code blocks.

| Variable | Value |
| --- | --- |
| `productName` | The product name |
| `projectName` | The project name |

The build fails if a page uses a variable that doesn't exist.

## Base path

If you deploy under a subpath (for example, `https://example.com/repo-name`), set `NEXT_PUBLIC_BASE_PATH` at build time:

```bash
NEXT_PUBLIC_BASE_PATH=/repo-name npm run build
```
